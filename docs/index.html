Firebase Google Sign-In và OTP qua email

Hướng dẫn từng bước cho ứng dụng Flutter: clone project, cấu hình Firebase, đăng nhập Google, rồi thêm xác thực OTP khi đăng ký. Bấm vào ảnh để phóng to.

Tổng quan

Hướng dẫn này đi cùng bài lab Authentication (Module 10, PRM393). Bạn sẽ clone một project Flutter có sẵn, rồi tự cấu hình và chạy theo từng bước. Có 2 bài tập, kiểm chứng bằng cách chạy app:

Bài tập 1

Firebase Google Sign-In

Tạo Firebase project, bật Authentication, Firestore + Rules, SHA, flutterfire configure, đăng nhập Google.

 Bài tập 2

OTP qua email

Gmail App Password, SMTP trong app_config.dart, đăng ký bằng OTP 6 số, 8 kịch bản kiểm thử.
Bài tập 2 dùng lại Firebase đã cấu hình ở Bài tập 1, nên hãy làm theo đúng thứ tự.

Luồng hoạt động của app

Đăng ký (Bài 2)

  1. Nhập tên, email, mật khẩu.
  2. App kiểm tra email đã có trên Firebase chưa (registered_emails). Có rồi thì báo lỗi.
  3. Chưa có: sinh OTP 6 số, gửi qua email (SMTP).
  4. Nhập OTP. Sai hoặc hết hạn thì báo lỗi, cho gửi lại.
  5. Đúng: tạo tài khoản Firebase Auth, lưu users/{uid}, quay về Đăng nhập.

Đăng nhập

  • Email + mật khẩu (Firebase Auth)
  • Google: google_sign_in → Firebase Auth → lưu users/{uid} (Bài 1)

Mục tiêu học tập

  • Cấu hình Firebase: Authentication, Firestore, Security Rules
  • Đăng ký app Android, thêm SHA, dùng FlutterFire CLI
  • Tích hợp Google Sign-In (OAuth 2.0)
  • Gửi và xác thực OTP: hết hạn, giới hạn lần thử, dùng một lần
  • Hiểu vì sao demo này chưa đủ an toàn cho hệ thống thật

Bài tập 1 – Firebase Google Sign-In

Mục tiêu: cấu hình Firebase cho app và đăng nhập thành công bằng Google; hồ sơ người dùng được lưu trên Firestore.

Bước 1. Tạo project Firebase

  • Mở https://firebase.google.com, bấm Go to console (chưa đăng nhập thì Sign in bằng Google) Hình 1 Hình 2.
  • Bấm Create a new Firebase project Hình 3.
  • Đặt tên (ví dụ test), bấm Continue Hình 4.
  • Gemini in Firebase Hình 5 và Google Analytics (có thể tắt) Hình 6: giữ mặc định. Nếu bật Analytics, chọn quốc gia, đồng ý điều khoản, Create project Hình 7.
  • Project tạo xong, mở nó từ danh sách Hình 8.
ID project do Firebase tự sinh nên sẽ khác trong ảnh.

Bước 2. Bật Authentication: Email/Password và Google

  • Mở Security → Authentication Hình 9, bấm Get started Hình 10.
  • Tab Sign-in method: chọn Email/Password Hình 11, bật dòng đầu tiên (không cần *Email link*), Save.
  • Chọn Google Hình 12, bật Enable, chọn *Project support email*, Save Hình 13.
Email/Password dùng cho Bài 2, Google dùng cho Bài 1. Quên *support email* thì đăng nhập Google lỗi ApiException: 12500.

Bước 3. Tạo Firestore Database

  • Databases & Storage → Firestore, bấm Create database Hình 14.
  • Chọn Standard edition, Next Hình 15.
  • Database ID để (default). Location gần Việt Nam, ví dụ asia-southeast1 (Singapore), Next Hình 16.
  • Chọn Start in production mode, Next Hình 17.
  • Bỏ qua *Scheduled backups*, bấm Create Hình 18.
  • Tạo xong, chuyển sang tab Rules Hình 19.

Bước 4. Publish Firestore Security Rules

  • Tab Rules đang chứa rules mặc định, từ chối mọi truy cập Hình 20.
  • Xoá hết, dán toàn bộ file firestore.rules (bên dưới), bấm Publish Hình 21.
  • Kiểm tra rules đã Publish Hình 22.
rules_version = '2';

service cloud.firestore {
  match /databases/{database}/documents {

    // Hồ sơ người dùng: chỉ chính chủ đọc/ghi.
    match /users/{uid} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
    }

    // Đánh dấu email đã đăng ký (kiểm tra trùng TRƯỚC khi gửi OTP).
    // - get: cho phép khi chưa đăng nhập (người dùng đang đăng ký)
    // - list: cấm, tránh liệt kê toàn bộ email
    // - create: chỉ khi đã đăng nhập (sau khi tài khoản được tạo)
    match /registered_emails/{key} {
      allow get: if true;
      allow list: if false;
      allow create: if request.auth != null;
      allow update, delete: if false;
    }
  }
}

Bước 5. Lấy SHA-1 / SHA-256 của máy build

SHA là bắt buộc để Google Sign-In chạy trên Android. Có 2 cách:

Cách 1 – Gradle:

cd android
./gradlew signingReport             # Windows: .\gradlew signingReport

Tìm khối Variant: debug, copy dòng SHA1 và SHA-256.

Cách 2 – đọc debug keystore:

keytool -list -v -alias androiddebugkey -storepass android -keypass android \
  -keystore ~/.android/debug.keystore
# Windows: -keystore %USERPROFILE%\.android\debug.keystore
Mỗi máy có debug keystore khác nhau, nên mỗi thành viên trong nhóm phải thêm SHA của máy mình.

Bước 6. Đăng ký app Android và thêm SHA

  • Project Overview, chọn biểu tượng Android Hình 23.
  • Android package name: com.example.flutter_otp_demo (trùng applicationId trong android/app/build.gradle.kts), Register app Hình 24.
  • Có thể đóng (X) cửa sổ hướng dẫn sau khi Register: tải file cấu hình và thêm SDK làm ở Bước 7, 8. App đã xuất hiện Hình 25.
  • Bấm bánh răng cạnh tên app, mở Project settings Hình 26.
  • Mục Your apps (Android), Add fingerprint Hình 27, dán SHA-1, Save. Lặp lại với SHA-256 Hình 28.

import 'package:firebase_core/firebase_core.dart' show FirebaseOptions;
import 'package:flutter/foundation.dart'
    show defaultTargetPlatform, kIsWeb, TargetPlatform;

class DefaultFirebaseOptions {
  DefaultFirebaseOptions._();

  static FirebaseOptions get currentPlatform {
    if (kIsWeb) {
      throw UnsupportedError('Chưa cấu hình Firebase cho Web.');
    }
    switch (defaultTargetPlatform) {
      case TargetPlatform.android:
        return android;
      default:
        throw UnsupportedError(
          'Chưa cấu hình Firebase cho $defaultTargetPlatform. '
          'Hãy chạy "flutterfire configure" và chọn thêm nền tảng này.',
        );
    }
  }

  static const FirebaseOptions android = FirebaseOptions(
    apiKey: 'AIza...',                          // current_key
    appId: '1:123456789:android:abcdef...',     // mobilesdk_app_id
    messagingSenderId: '123456789',             // project_number
    projectId: 'ten-project',                   // project_id
    storageBucket: 'ten-project.firebasestorage.app',
  );
}

Bước 8. Kiểm tra plugin Google Services trong Gradle

GoogleSignIn() trong auth_service.dart không truyền serverClientId, nên trên Android plugin com.google.gms.google-services là bắt buộc. Nếu flutterfire configure chưa thêm, tự thêm dòng có chú thích thêm (Firebase cũng gợi ý như Hình 29).

android/settings.gradle.kts:

plugins {
    id("dev.flutter.flutter-plugin-loader") version "1.0.0"
    id("com.android.application") version "..." apply false
    id("org.jetbrains.kotlin.android") version "..." apply false
    id("com.google.gms.google-services") version "4.4.2" apply false   // thêm
}

android/app/build.gradle.kts:

plugins {
    id("com.android.application")
    id("com.google.gms.google-services")                                 // thêm
    id("dev.flutter.flutter-gradle-plugin")
}
Lỗi minSdk thì đặt minSdk = 23 trong android/app/build.gradle.kts.

Mở máy ảo Android (hoặc điện thoại bật *USB debugging*):

Bài tập 2 – OTP qua email khi đăng ký

Mục tiêu: hoàn thiện cấu hình gửi OTP và xác thực OTP trong luồng đăng ký. Cần Firebase đã cấu hình xong ở Bài 1.

Bước 1. Tạo App Password cho Gmail

  1. Với Gmail dùng để gửi OTP, bật Xác minh 2 bước.
  2. Mở https://myaccount.google.com/apppasswords, tạo Mật khẩu ứng dụng (16 ký tự).

Bước 2. Điền SMTP vào app_config.dart

Sửa lib/config/app_config.dart:

static const String smtpUser = 'ten_ban@gmail.com';
static const String smtpAppPassword = 'abcd efgh ijkl mnop';
  • App Password gồm 16 chữ cái, viết liền hay có dấu cách đều được.
  • Không dùng mật khẩu Gmail thường (lỗi 535 Username and Password not accepted).
Bảo mật: App Password nằm trong mã nguồn. Không push app_config.dart có mật khẩu thật lên GitHub công khai. Nếu lỡ lộ, xoá ở https://myaccount.google.com/apppasswords và tạo mới.
Chưa cấu hình SMTP? App vẫn chạy ở *chế độ dev*: không gửi email, mã OTP được in ra Debug Console / logcat.

Bước 3. Chạy app và đăng ký bằng email thật

flutter run
  • Ở màn Đăng nhập bấm Đăng ký, nhập tên, email truy cập được, mật khẩu (tối thiểu 8 ký tự, gồm chữ và số).
  • Email OTP đến trong vài giây (xem cả thư mục Spam).
  • Gửi lỗi thì thông báo hiện trên màn hình và trong Debug Console.

Bước 5. Tìm hiểu quy tắc bảo mật OTP

Đọc lib/config/app_config.dart và lib/services/otp_service.dart, đối chiếu:

Khác biệt giữa demo và hệ thống thật:

  • OTP sinh và kiểm tra ngay trong app, nên có thể bị can thiệp. Thực tế phải sinh và xác thực OTP ở server (Cloud Functions, backend riêng) và chỉ tạo tài khoản khi server xác nhận.
  • Thông tin SMTP nằm trong app, có thể bị trích từ APK. Thực tế gửi mail từ server hoặc dùng SendGrid / Firebase Extension *Trigger Email*.
  • registered_emails chỉ cho get (không list) để hạn chế dò danh sách email, nhưng vẫn có thể dò từng email. Đây là đánh đổi để kiểm tra trùng trước khi gửi OTP.
  • Package mailer dùng socket, chạy Android/iOS, không chạy Flutter Web.
